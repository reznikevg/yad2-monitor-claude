# מוניטור דירות ליד2 → טלגרם — מדריך הקמה

פתרון עובד בפועל (רץ אצלי עכשיו) שסורק חיפושי שכירות בליד2 כל 30 דקות ושולח הודעת טלגרם רק כשיש דירה חדשה או מודעה שהשתנתה (מחיר, קומה וכו׳). רץ בענן בחינם (GitHub Actions), בלי שרת ובלי תשלום.

## מה מצורף

| קובץ | ליעד בריפו שלך | חובה? |
|---|---|---|
| `yad2_monitor.py` | שורש הריפו | כן |
| `requirements.txt` | שורש הריפו | כן |
| `monitor.yml` | `.github/workflows/monitor.yml` | כן |
| `worker.js` | `cf-worker/src/worker.js` | רק אם מקור מסוים נחסם גם עם curl_cffi |
| `wrangler.toml` | `cf-worker/wrangler.toml` | רק אם משתמשים ב-worker.js |

זה הקוד המלא שרץ אצלי, ללא שינוי — לא דמו, לא סקיצה. השינויים היחידים שנעשו: הסרתי את ה-`account_id` הפרטי מ-`wrangler.toml` והחלפתי בפלייסהולדר.

## התמונה הגדולה

```
GitHub Actions (cron כל 30 דק׳)
        │
        ▼
yad2_monitor.py
   ├─ שולף דירות מה-API הפנימי של ליד2 (מהיר, בלי דפדפן)
   │     └─ אם חסום → Playwright (דפדפן headless) כ-fallback
   ├─ משווה מול state שנשמר בריפו (state/*.json)
   ├─ בונה הודעה רק על מה שחדש/השתנה
   └─ שולח POST לבוט טלגרם
        │
        ▼
   git commit את ה-state המעודכן בחזרה לריפו
```

כל ריצה עצמאית — אין שרת שרץ ברקע, ה"זיכרון" בין ריצות הוא קובץ JSON ששמור בגיט.

## הרכיבים

### 1. בוט טלגרם
נכנסים ל-`@BotFather` בטלגרם, `/newbot`, מקבלים **token**. שולחים הודעה לבוט מהחשבון האישי, ואז קוראים ל:
```
https://api.telegram.org/bot<TOKEN>/getUpdates
```
מוציאים משם את ה-`chat_id` שלכם. את שני אלה **לא** שמים בקוד — הם נכנסים כ-GitHub Actions Secrets (`TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`).

### 2. שליפת הדירות — שתי שכבות
ליד2 מוגן ב-Radware (WAF שחוסם בקשות מזוהות כבוטים — כולל IP-ים של GitHub Actions). לכן יש שתי שיטות, בסדר הזה:

**שכבה א׳ — קריאת API ישירה** ל-`gw.yad2.co.il/realestate-feed/rent/map` עם הפרמטרים של החיפוש (מחיר, חדרים, שכונה וכו׳). מהירה ואמינה, אבל צריך "להתחזות" לדפדפן אמיתי כדי לעבור את ה-WAF:
- הפתרון: החבילה `curl_cffi` — עוטפת בקשת HTTP עם **טביעת אצבע TLS** של Chrome אמיתי (`impersonate="chrome120"`), בניגוד ל-`requests` הרגילה שה-WAF מזהה ומחסום.

**שכבה ב׳ — Playwright (דפדפן headless) כ-fallback**, רק אם ה-API נכשל: פותח את דף החיפוש, מחכה שהתוכן ה-JS ייטען, גולל למטה כמה פעמים כדי לטעון עוד תוצאות, ומחלץ את הדאטה משני מקורות במקביל — `window.__NEXT_DATA__` (הדאטה הגולמי שה-React מקבל מהשרת, הכי אמין) ובגיבוי גם סריקת ה-DOM עצמו.

> טיפ: אם מקור מסוים ממשיך להיחסם גם עם `curl_cffi`, יש אופציה לנתב את הבקשה דרך **Cloudflare Worker** (פרוקסי קטן שרץ בתוך רשת Cloudflare, ולכן לא נחסם כ-IP של דאטהסנטר). ראו `cf-worker/src/worker.js` — פרוקסי מינימלי שמעביר בקשה ל-`gw.yad2.co.il` עם ה-headers הנכונים.

### 3. זיהוי שינויים (deduplication)
לכל מודעה בונים hash מהשדות המשתנים (`id|price|rooms|floor|address|description`). משווים מול ה-state הקודם:
- ID חדש → **דירה חדשה**
- ID קיים אבל hash שונה → **עודכן** (שולחים אילו שדות השתנו, ישן→חדש)
- ID שנעלם → מתעלמים בשקט, לא מתריעים על "הוסר"

State נשמר לכל מקור חיפוש בנפרד (קובץ JSON), נכתב אטומית (כתיבה ל-`.tmp` ואז `rename`).

### 4. אמינות
- **סף כשלים רצופים** לפני שליחת התרעת שגיאה לטלגרם (כדי לא להציף בהודעות אם ליד2 חוסם באופן זמני) — נספר per-source ונשמר ב-state.
- אם השליחה לטלגרם עצמה נכשלת — נכתב לקובץ `failed_alerts.txt` במקום לאבד את ההתרעה.

### 5. הרצה מתוזמנת — GitHub Actions
קובץ `.github/workflows/monitor.yml`:
- `cron: '*/30 3-20 * * *'` — כל 30 דקות, 06:00–24:00 שעון ישראל
- קרון נוסף פעם ביום לסיכום כל הדירות השמורות (`--summary`)
- ה-workflow: מתקין תלויות → מריץ את הסקריפט עם ה-secrets כ-env vars → אם ה-state השתנה, עושה `git commit` + `git push` בחזרה לריפו (עם `permissions: contents: write`)

יתרון הגישה הזו: אין שרת להחזיק, אין עלות, וה"מסד נתונים" הוא פשוט קבצי JSON בגיט.

## שלבי הקמה בפועל

1. **צור בוט טלגרם** (BotFather) → קבל token. שלח לבוט הודעה כלשהי, ואז גש ל-`https://api.telegram.org/bot<TOKEN>/getUpdates` כדי לחלץ את ה-`chat_id`.
2. **צור ריפו חדש בגיטהאב** (יכול להיות פרטי). שים את `yad2_monitor.py` ו-`requirements.txt` בשורש, ואת `monitor.yml` בתוך `.github/workflows/`.
3. **הגדר את החיפוש שלך** — ב-`SOURCES` בתוך `yad2_monitor.py`, שים את ה-`url` וה-`api_url` המתאימים לחיפוש שלך בליד2 (פותחים את חיפוש ליד2 בדפדפן עם הפילטרים הרצויים ומעתיקים את שני הכתובות — הרגילה ואת זו שמתחילה ב-`gw.yad2.co.il` מתוך Network tab בדפדפן).
4. **הוסף Secrets בריפו** (Settings → Secrets and variables → Actions): `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`. אל תשים אותם בקוד.
5. **Push** — אין צורך ליצור ידנית את תיקיית `state/`, הסקריפט יוצר אותה לבד בריצה הראשונה ומוסיף לגיט.
6. **הפעל ידנית פעם אחת** (Actions → Yad2 Monitor → Run workflow → `workflow_dispatch`) ותבדוק שההודעה הראשונה הגיעה לטלגרם, לפני שסומכים על הקרון.
7. **אופציונלי — Cloudflare Worker:** רק אם אחרי כמה ריצות רואים בלוגים שמקור מסוים נחסם גם עם curl_cffi. אז: `cf-worker/` → `wrangler deploy` (עם חשבון Cloudflare חינמי), ומגדירים `WORKER_PROXY` כ-repo variable עם כתובת ה-worker שקיבלתם.
8. **אופציונלי:** קרונטאב מקומי במחשב כגיבוי מקביל (למקרה שגיטהאב עצמו ייחסם) — רק לשים לב שאז יש שני state עצמאיים ואפשר לקבל אותה התרעה פעמיים.

## הטעויות שנפלנו בהן (שווה לדעת מראש)

- **בקשת `requests` רגילה מ-GitHub Actions נחסמת תמיד** — Radware מזהה IP-ים של דאטהסנטרים. זה מה שהוביל ל-`curl_cffi`.
- **"success" ב-GitHub Actions לא אומר שהיו תוצאות** — סקריפט יכול "להצליח" ולהחזיר 0 דירות כי החסימה מחזירה HTML ולא שגיאת HTTP. יש בדיקה מפורשת ל-`content-type` כדי לתפוס את זה.
- **אל תשים טוקן/סוד בקובץ בקוד** — רק ב-Secrets של גיטהאב / משתני סביבה. גם קובץ תיעוד (README/SKILL) לא אמור להכיל טוקן אמיתי בטקסט חופשי.
- **שני מוניטורים עצמאיים (ענן + מקומי) = כפילות אפשרית בהתרעות** — אין דדופליקציה משותפת ביניהם כרגע; אם זה מפריע, הפתרון הוא state משותף.
